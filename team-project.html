  • 산출물 형식·최종 마감: 미확인 → PLMS 공지 확인 필요

주제 후보 v1 (폐기: 너무 쉬움 — 아래 v2로 대체, 2026-10-21)

교수님 요구 구조: 산업 선택 → 제품 차별화 → 가격 전략. 수업에서 배운 모형(보완재·잠금, 묶음 가격, 수요곡선 추정, 탄력성, 해 찾기)을 그대로 적용할 수 있는 것으로 골랐음.

후보 1: 캡슐 커피 (기기 + 캡슐)

  • 산업: 홈카페/캡슐 커피 (네스프레소, 일리 등)
  • 차별화: 머신 성능보다 캡슐 라인업·구독으로 차별화 (기본/프리미엄 캡슐, 정기배송)
  • 가격 전략: 면도기-날 모형 (4강). 머신은 싸게, 캡슐에서 이익 → 머신 가격 vs 캡슐 마진의 최적 조합을 해 찾기로
  • 데이터: 공개된 머신·캡슐 가격, 시장 규모 자료 많음. 수업 모형 그대로라 발표 설계 쉬움
  • 팀 적합도: 구조가 단순해 5명이 나누기 쉬움 (수요 추정 / 모형 / 엑셀 / 발표)

후보 2: 모바일 게임 부분유료화 (F2P + 배틀패스)

  • 산업: 모바일 게임
  • 차별화: 장르·IP 대신 과금 구조로 차별화 (무료 진입 + 배틀패스/스킨 묶음)
  • 가격 전략: 묶음 가격 모형 (5강 Verizon) + 잠금. 배틀패스 묶음의 최적 가격, 개별 판매 대비 묶음 이익 비교
  • 데이터: 앱스토어 가격 공개, 매출 추정 자료(센서타워 등 요약 기사) 활용 가능
  • 팀 적합도: 컴공+전자 조합에 친숙한 주제, 묶음 모형은 수업 엑셀 재활용 가능

후보 3: 음악/OTT 스트리밍 요금제

  • 산업: 스트리밍 구독 (유튜브 프리미엄, 멜론, 넷플릭스 등)
  • 차별화: 콘텐츠가 아니라 요금제 구조로 차별화 (광고형/기본/프리미엄, 학생·가족 요금)
  • 가격 전략: 버전 차별화 + 가격 차별. 요금제 간 가격 격차와 탄력성으로 최적 요금 설계, 광고형 도입의 cannibalization 분석
  • 데이터: 요금 공개, 학생 할인 사례 풍부. 설문으로 팀이 직접 지불의사 데이터 만들기도 쉬움
  • 팀 적합도: 설문+엑셀 분석으로 역할 나누기 좋고, 현실감 있는 주제

세 개 다 수업 엑셀(수요 추정 → 해 찾기)로 실제 숫자를 돌려볼 수 있어서 "숫자로 어떤 결정을 할 것인가"라는 교수님 포인트에 맞음.

주제 후보 v2 (야심찬 버전, 2026-10-21)

피드백 반영: v1은 너무 쉬움. 수업 모형(수요 추정·탄력성·보완재·묶음·버전 차별화·해 찾기)을 쓰되, 실제 데이터나 시뮬레이션으로 한 단계 더 가는 주제 3개.

후보 1: AI 구독 vs 사용량 과금 — ChatGPT류 서비스의 최적 가격 구조

  • 산업: 생성형 AI 구독/API (ChatGPT Plus, Claude, API 토큰 과금)
  • 차별화: 모델 크기·응답 품질·속도로 버전 차별화 (무료/Plus/Pro/API), 정액제와 종량제의 하이브리드 설계
  • 가격 전략: 버전 차별화 + 묶음(정액) + 사용량 과금 비교. 토큰당 실제 추론 원가(GPU 시간)를 직접 추정하고, 지불의사 설문(학생 대상)과 공개 요금으로 수요곡선 추정 → 어떤 구조가 이익 최대인지 해 찾기/시뮬레이션
  • 데이터: API·구독 공개 요금, GPU 시세, 팀 설문. 창민이 모델 경량화 연구 중이라 원가 추정에 진짜 강점
  • 교수님 포인트: 지금 가장 뜨거운 시장의 가격 구조를 원가+수요 양쪽 숫자로 분석. "정액제는 과소비를 부르는가" 같은 날카로운 질문 가능
  • 리스크: 시장이 계속 바뀜(요금 인상/신제품), 기업 실제 수요 데이터는 비공개라 추정 의존

후보 2: 전기차 충전 다이내믹 프라이싱 + 배터리 구독 (BaaS)

  • 산업: 전기차/충전 인프라
  • 차별화: 충전 속도·위치·예약 서비스로 차별화, 배터리는 소유 대신 구독 (NIO BaaS 모델)
  • 가격 전략: 시간대별 다이내믹 프라이싱 — 한전 시간대별 실제 전력요금 데이터로 충전 수요를 가격으로 이동시키는 최적 요금표 설계 + 차량-충전 보완재(면도기-날 확장)로 차량가 vs 충전 마진 최적화. 간단한 시뮬레이션으로 시간대별 수요 이동 검증
  • 데이터: 한전 시간대별 요금 공개, 충전사업자 요금(환경부·사업자 공개), BaaS 해외 사례. 전자+반도체 팀원에게 익숙한 산업
  • 교수님 포인트: 수업 모형(보완재)에 "시간" 차원을 얹은 확장 — 정적 모형 너머로 한 단계. 실제 정책 데이터 사용
  • 리스크: 국내 충전 수요 미시 데이터가 부족해 탄력성은 가정/문헌 값 사용, BaaS 국내 사례 적음

후보 3: HBM vs 범용 DRAM — 반도체의 제품 차별화가 가격을 바꾸는 구조

  • 산업: 메모리 반도체 (SK하이닉스·삼성, HBM 중심)
  • 차별화: 커머디티 DRAM(가격 경쟁) → HBM(성능 차별화, 장기 공급 계약) 전환이 탄력성과 마진 구조를 바꾸는 것을 분석
  • 가격 전략: 차별화 → 탄력성 하락 → 가격 결정력 상승의 체인을 수업 프레임으로 모형화. 사이클에 따른 가격 변동(커머디티)과 계약 기반 가격(HBM) 비교, 장기계약 묶음의 가치 평가
  • 데이터: TrendForce·DRAMeXchange 공개 요약, 두 회사 IR/실적발표 자료, 뉴스. 팀원 D(반도체공학과) 도메인 지식 활용
  • 교수님 포인트: 수업이 다루는 B2C 위주에서 벗어나 B2B 가격 결정 구조를 보여주는 차별성. "차별화가 곧 가격 결정력"이라는 수업 메시지의 산업 증명
  • 리스크: B2B 미시 데이터 부족으로 수요곡선 추정이 정성적일 수 있음, 매크로(사이클) 얘기로 흐르면 과제 범위를 벗어남 — 모형 중심으로 잡아야 함

셋 다 팀 구성(컴공+반도체+전자)의 기술 강점을 쓰고, 실제 데이터/시뮬레이션으로 "숫자로 어떤 결정?"에 답하는 구조. 1번이 데이터 접근성 최고, 2번이 모형 확장성 최고, 3번이 차별성 최고.

추론 (라벨: 추측)

  • 과제 의도는 새 방법론이 아니라 "수업 프레임 전체를 처음부터 끝까지 한 번 돌려보는 것": 산업 선택 → 차별화 설계(버전 나누기) → 데이터로 수요 추정 → 해 찾기로 최적 가격 → "이 숫자로 어떤 결정?"으로 마무리. 숙제의 확대판일 가능성이 큼
  • 채점이 상을 주는 지점: (1) 수업 모형에 주제가 깨끗이 대응되는가 (2) 수요 추정을 실제로 엑셀로 했는가 (3) 마지막에 경영적 결정을 내리는가. 기술적 난이도 자체는 점수가 아닐 가능성이 높음 ("최적화 수업 아님"을 여러 번 못박음)
  • 역설: v1이 "너무 쉽다"고 느낀 이유(수업 모형 그대로)가 오히려 채점 기준에는 부합. 야심은 방법론이 아니라 데이터의 진짜배기와 결정의 날카로움으로 내야 함

의도 기준 재평가 (v2 후보 3개)

  • 후보 1 AI 구독: 적합도 높음. 버전 차별화 + 정액(묶음) vs 종량이 수업 프레임에 정확히 대응, 설문 수요 추정은 수업 방식 그대로, "팀이 관심 있는 서비스"라는 메일 조건에도 맞음. 단, GPU 원가 시뮬레이션 같은 CS 파트는 빼고 엑셀 마케팅 분석으로 실행해야 함 — 그대로 하면 최선
  • 후보 2 EV 충전: 보완재 확장은 좋지만 시간대별 다이내믹 프라이싱+시뮬레이션은 수업이 안 다룬 방법론이라 "최적화 수업화" 위험. 살리려면 다이내믹 시뮬 대신 피크/오프피크 두 버전 정적 가격(버전 차별화)으로 축소
  • 후보 3 HBM: 차별화→탄력성 서사는 수업 주제와 맞지만, B2B라 엑셀로 수요곡선을 추정할 데이터가 없어 파이프라인 실행이 불가능에 가까움. 점수 리스크가 가장 큼
  • 순위: 1번 > (안전 대안: v1 캡슐커피 — 의도 적합도는 최고지만 참신성 낮음) > 2번(축소 시) > 3번
  • 추천: 1번을 하되, 발표 구조를 교수님 파이프라인 순서로 — 차별화(요금제 버전) → 설문 수요 추정 → 해 찾기 최적 요금 → 결정("학생 시장에선 정액 vs 종량 중 이것")

각 단계에 "왜 이렇게 하는가"를 교수님 채점 의도와 근거 자료에 연결해 적음. 추측은 (추측) 표시.

0. 이 주제를 고른 이유

  • 교수님 의도(근거: 수업 노트): 숙제가 "수업에서 한 걸 다른 사례로 다시 하기"로 운영됨 → 팀 프로젝트는 이 패턴의 확대판, 즉 수업 프레임(차별화 → 수요 추정 → 해 찾기 → 결정)을 새 산업에 완주하는 과제일 가능성이 큼 (추측)
  • 채점은 손채점, "내 형식 아니어도 함수만 맞으면 OK", "최적화 수업이 아니라 마케팅 분석 수업" → 기술 난이도가 아니라 모형 설정과 해석이 점수
  • 10/15 메일: "관심 있는 제품/서비스"를 고르라고 함 → 팀 전원이 실사용자인 AI 서비스는 이 조건에 가장 잘 맞음
  • 데이터 접근성: 구독료·API 요금·GPU 시세가 전부 공개. 학생 설문으로 지불의사도 직접 만들 수 있어 파이프라인 전 단계를 실제 숫자로 돌릴 수 있음
  • 다른 후보를 뺀 이유: EV 충전은 다이내믹 프라이싱+시뮬레이션이라 수업이 안 가르친 방법론(최적화 수업화 위험), HBM은 B2B라 수요곡선을 추정할 데이터가 없음

1. 산업 선택 - 생성형 AI 구독/API 시장

  • 하는 일: 시장 범위를 정함 (소비자 구독 + 개발자 API, 한국 학생 시장 중심)
  • 왜: 교수님 과제 문구가 "산업 하나"를 고르고 시작하라는 것. 범위를 좁혀야 뒤의 수요 추정이 현실이 됨. 소비자(B2C) 중심으로 잡는 이유는 수업 모형이 전부 B2C 사례(면도기, Bakery, Verizon)라 그대로 대응시키기 위함

2. 차별화 설계 - 요금제 버전 나누기

  • 하는 일: 무료 / Plus급 정액 / Pro급 정액 / API 종량제의 버전 구조를 정리하고, 차별화 축(모델 품질·사용량 상한·속도)을 명시
  • 왜: 수업의 제품 차별화 단원(Basic/Premium, 카페, 광고 예제)이 정확히 이 구조. 교수님 과제 문구의 "제품 차별화"는 신제품 개발이 아니라 수업처럼 버전을 나누고 각 버전의 가치를 정하는 것을 뜻한다고 읽는 게 자연스러움 (추측이지만 단원 구성이 근거)
  • 발표에서 점수 받는 포인트: 차별화 축을 "우리가 정한" 것이 아니라 실제 서비스들의 요금표에서 관찰된 축으로 제시

3. 수요 추정 - 설문 + 공개 데이터

  • 하는 일:
  • 설문: 포스텍 학생 약 100명 대상. 지불의사 4문항(Van Westendorp: 너무 비쌈/비싸지만 고려/적정하다고 느낌/너무 싸서 의심) + 사용 빈도 + 정액 vs 종량 선호 + 버전 선택 실험
  • 공개 데이터: 구독료·API 요금표, GPU 시간당 시세로 추론 원가 추정
  • 분석: 가격-수요 곡선 추정 (피벗 + 회귀), 탄력성, 버전별 수요 분리
  • 왜 Van Westendorp인가: 수요곡선은 가격별 구매 의향 데이터가 있어야 그릴 수 있는데, 학생 팀이 유일하게 만들 수 있는 데이터가 지불의사 설문이기 때문. 4문항이면 응답 부담이 작아 100명 회수가 가능하고, 응답 분포를 누적하면 가격별 수요로 바로 변환됨
  • 왜 원가 추정이 들어가는가: 이익 = (가격 - 원가) x 수요라서 최적화에 원가가 필요. GPU 시세 기반 추정은 "추정"임을 명시하고 민감도 분석(원가 ±50%)으로 보완
  • 교수님 포인트와의 연결: "간단한 엑셀은 AI도 하지만 직접 한 걸 제출하라" → 설문을 직접 돌려 직접 추정하는 게 이 요구에 대한 답

4. 최적화 - 해 찾기

  • 하는 일: 변수(구독료, 토큰 단가) → 목적함수(이익) → 제약(수요곡선, 원가 하한) → 해 찾기(Solver). 정액 / 종량 / 하이브리드 3구조의 최적 이익을 비교
  • 왜: 퀴즈와 숙제가 전부 엑셀+해 찾기 형식이고 교수님이 "문제를 모형으로 세우는 게 중요, 그다음은 해 찾기 누르면 됨"이라고 반복함 → 프로젝트에서도 같은 도구를 쓰는 것이 의도에 맞음
  • 그림자 가격 해석까지 포함: 수업에서 라그랑주 승수 = 그림자 가격 해석을 강조했으므로, 제약(예: 무료 사용자 유입 최소치)의 그림자 가격을 해석하는 절을 넣으면 차별점 (추측)

5. 결정 - "이 숫자로 어떤 결정?"

  • 하는 일: 결론을 결정 한 문장 + 근거 숫자 2~3개로 작성. 예: "학생 시장 진입은 종량이 아니라 저가 정액이 이익 최대, 최적가는 월 X원 (탄력성 Y 근거)"
  • 왜: 교수님이 매 수업 "숫자만 보지 말고 이걸로 어떤 결정을 할 수 있는지"를 물음 → 발표의 마지막 장이 이 질문에 대한 답이어야 함. 여기가 약하면 앞의 분석이 다 흐려짐 (추측)

역할 분담 (초안, 첫 모임에서 확정)과 근거

  • 강창민 (팀장, 컴공): 모형 설계 + 해 찾기, 추론 원가 추정. 근거: 모델 경량화 연구 중이라 토큰 원가 구조를 가장 잘 앎, 조 첫 번째 이름으로 교수님이 연락 총괄로 지목
  • 팀원 D (반도체): 공개 요금·GPU/하드웨어 원가 데이터 수집. 근거: 하드웨어 전공이라 GPU 시세·원가 자료를 읽는 눈이 있음
  • 팀원 E (전자): 설문 문항 설계 + 통계 분석(회귀·탄력성). 근거: 공학 계열 통계/실험 설계 훈련과 맞음 (추측 - 전공 기반 배정, 모임에서 조정)

  • 팀원 C (무은재, 알리미): 발표 자료·스토리라인. 근거: 알리미(홍보 봉사단) 활동 이력이 메일로 확인됨 → 글·자료 작성 경험

팀 프로젝트 계획서: AI 구독 vs 사용량 과금 - 최적 가격 구조 분석

CMEF499D-01 Group 3 (강창민 외 4명) \| 2026-10-21 초안

형식 안내: 학교/교수님 지정 계획서 양식은 미확인 — 양식이 나오면 이 내용을 옮겨 담음.

1. 주제와 선정 배경

생성형 AI 서비스는 정액 구독(묶음)과 API 종량제(개별)라는 두 가격 구조가 공존하는 드문 시장이다. 우리 팀은 이 시장을 골라, 어떤 가격 구조가 왜 이익을 극대화하는지를 수요 추정과 최적화로 분석한다.

선정 이유: (1) 팀 전원이 실사용자라 문제 이해가 빠르고, (2) 구독료·API 요금·GPU 시세가 공개되어 실제 숫자로 분석 가능하며, (3) 수업에서 배운 버전 차별화·묶음 가격·수요 추정 프레임이 그대로 적용된다.

2. 연구 질문

Q1. 학생 소비자 시장에서 AI 서비스의 최적 요금제 구조는 정액, 종량, 하이브리드 중 무엇인가?

Q2. 그 구조 안에서 최적 가격은 얼마인가?

Q3. 그 숫자로 기업(또는 학생 소비자)은 어떤 결정을 해야 하는가?

3. 분석 방법

3.1 차별화 구조 정리

실제 서비스(ChatGPT, Claude, Gemini 등)의 요금표를 수집해 버전(무료/표준/프로)과 차별화 축(모델 품질, 사용량 상한, 속도)을 정리한다. 이 단계는 수업의 제품 차별화 단원(Basic/Premium, 카페 예제)과 같은 구조로 정리해, 차별화가 가격 격차의 근거가 됨을 보인다.

3.2 수요 추정

학생 대상 설문(제4절)으로 가격별 지불의사 분포를 얻고, 누적 분포를 가격-수요 곡선으로 변환한다. 피벗 테이블과 회귀로 수요 함수를 추정하고 탄력성을 계산한다. 버전별 수요를 분리해 버전 간 이동(cannibalization)도 추정한다.

3.3 원가 추정

토큰당 추론 원가를 GPU 시간당 시세와 모델당 처리량 가정으로 추정한다. 추정치임을 명시하고 원가 ±50% 민감도 분석을 함께 제시한다.

3.4 최적화

엑셀 해 찾기(Solver)로 이익 = (가격 - 원가) x 수요를 최대화하는 가격을 구한다. 정액 / 종량 / 하이브리드 3개 구조를 각각 최적화해 최적 이익을 비교한다. 제약(예: 무료 버전 유지, 최소 시장점유)의 그림자 가격도 해석한다.

3.5 결정 도출

분석 결과를 "이 숫자로 어떤 결정을 할 것인가"로 마무리한다. 예: 학생 시장 진입 전략(정액 vs 종량), 학생 할인의 최적 가격대, 무료 버전 유지 여부.

4. 설문 조사 계획

  • 대상: 포스텍 학생 약 100명. 배포: 단과대 단톡방, 에브리타임
  • 기간: 11/1~11/4 (나흘)

문항 초안:

  • 1. AI 챗봇/도구를 얼마나 자주 쓰나요? (매일/주 3회 이상/주 1~2회/거의 안 씀)
  • 2. 현재 유료 AI 서비스를 결제하고 있나요? (있다/없다 - 있다면 서비스와 요금제)
  • 3. (지불의사) 월 구독 서비스가 있다고 할 때: 얼마부터 너무 비싸서 안 사겠습니까? / 얼마면 비싸지만 고려하겠습니까? / 얼마면 적정하다고 느끼겠습니까? / 얼마 이하면 너무 싸서 품질이 의심되겠습니까?
  • 4. 정액제(무제한 느낌)와 종량제(쓴 만큼) 중 선호는? 그 이유는?
  • 5. 무료/표준(월 X원)/프로(월 Y원) 버전이 있을 때 어느 것을 고르겠습니까? (X, Y는 3문항 응답 분포를 보고 결정)
  • 분석: 3문항 누적 분포 → 수요곡선, 5문항 → 버전별 수요와 cannibalization
